#10 索引并发控制：Latch 与 Latch Crabbing
Latch Crabbing：读蟹行 · 悲观写 · 乐观写 · 叶子扫描		读操作的蟹行724.5s读 latch 徽章沿指针从父节点飞到孩子、落地涟漪；游标随后下移；父节点的徽章缩小消失；两个线程的徽章在同一节点并排
悲观写：安全才放祖先928.0s写 latch 徽章逐层飞向孩子；孩子不安全时祖先的徽章留在原地，安全时自上而下依次缩小消失；T2 的等待徽章停在根旁，根一放开就滑进槽位
乐观写：先赌后验1038.1s两个线程的读 latch 徽章并排落在根上、各自蟹行下探；到叶子换成实心的写徽章；猜错的线程徽章全部缩回、游标退出，再从根用写徽章重走一遍
叶子扫描：No-Wait1034.7s两个线程的徽章沿兄弟指针相向飞行、两个游标对穿交换位置；读者撞上写 latch 时等待徽章停在外侧；三个选项依次弹出、被划掉或点亮；放弃的线程徽章缩回、红点飞回起点后重试

一句话：这门课从零剖开一个数据库管理系统（DBMS）的内部构造。

Andy 第一节课就把话说死了。这不是一门教你怎么用数据库的课。 它不教写业务 SQL，不教调 MySQL 参数，也不教 DBA 运维。在 CMU，那些内容归信息系统学院。

这门课站在计算机科学的层面。它只问一件事：你敲下一句 SELECT 之后，软件内部到底发生了什么。

SELECT * FROM student WHERE name = 'Andy';   -- 你只写了这一行
-- 优化器：挑一个最快的执行计划
-- 执行引擎：算子一层层把元组往上传
-- 存储管理：缓冲池把要用的页从磁盘读进内存

整门课的主线，就是自底向上重建一个数据库。
